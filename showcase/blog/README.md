# Nova Blog — the "PetClinic" equivalent

A complete REST API for blog posts, backed by sqlite, built with Nova Boot
and `nova db pull` models. It really runs and really serves HTTP.

## What it shows

| Nova feature | Where |
|---|---|
| `nova db pull` model generation | `models.nova` (generated — read the header) |
| Check-time column validation (`E_DB_SCHEMA`) | `api.nova:29` — try `dbTable(db, "postz")` |
| Typed path params (`/posts/{id: Int}`) | `api.nova:46` |
| JSON binding (Nova types as schema) | `api.nova:63-75` (createPost validation) |
| `Result[Response, Response]` → HTTP mapping | every handler; `Err` serves that status |
| `?` for error threading in handlers | `api.nova:27`, `api.nova:52` |
| Query builder (select/where/orderBy/first) | `api.nova:27-28`, `api.nova:52` |
| `dbExec` for writes | `api.nova:78`, `api.nova:99`, `api.nova:115` |
| Global `Db` handle pattern | `api.nova:13`, `api.nova:136` |
| Request logging | automatic — watch stdout |

## How to run

From the `nova-lang` directory:

```bash
# 1. (already done) generate models from the sqlite schema:
./nova db pull --dsn sqlite:///showcase/blog/blog.db \
  --out showcase/blog/models.nova

# 2. serve:
NOVA_PORT=8081 ./nova run showcase/blog/api.nova
```

Try it:

```bash
curl localhost:8081/posts
curl localhost:8081/posts/1
curl localhost:8081/posts/abc        # 400: path param 'id' must be Int
curl localhost:8081/posts/99         # 404: no post 99
curl -X POST localhost:8081/posts \
  -d '{"title":"Hi","body":"...","created_at":"2026-10-10"}'
curl -X POST localhost:8081/posts -d '{"body":"x"}'
# 400: {"error":"missing field 'title'"}
```

## Key design points (for the React dev)

**Handlers return `Result[Response, Response]`.** `Ok` is the happy path;
`Err(response)` serves *that* HTTP response. There is no exception-based
control flow, no middleware catching throws — the type tells you exactly
which HTTP statuses a handler can produce. Compare: Express `res.status(400).json(...)`
scattered through callbacks; here the 400 is a value.

**The database handle is a global `Option[Db]`.** Handlers take only
`(req: Request)`, so shared state lives in globals. `boot()` opens the db
before `serve()` blocks; `getDb()` (api.nova:16) turns "not open" into a
500. This is the honest version of dependency injection for a
single-process server.

**Column names are checked.** `.nova-schema.json` (written by `nova db pull`)
lets `nova check` reject `dbTable(db, "postz")` with `E_DB_SCHEMA` before
you run. It is best-effort (literals only), and the README of
`docs/v2.1-database.md` says so.

**Writes use `dbExec`.** v2.1 has no prepared-statement binding; `createPost`
inlines values into SQL. `sqlQuote` (api.nova:122) is documented as
escaping, not binding — the seam for real bound parameters is `dbExec`'s
SQL string. Do not use this pattern with untrusted input in production.

## Files

- `api.nova` — the server (CRUD handlers + boot).
- `models.nova` — generated by `nova db pull`; DO NOT EDIT.
- `.nova-schema.json` — generated; drives `E_DB_SCHEMA`.
- `blog.db` — the sqlite database (2 seed posts).
