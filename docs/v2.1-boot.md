# Nova Boot — the batteries-included web framework

Nova Boot is Nova's answer to Spring Boot: a web framework in the standard
library with zero configuration. You describe routes; Nova serves HTTP.

```nova
import std.web

effect fn hello(req: Request) -> Result[Response, Response] {
  return Ok(web.ok("hello"))
}

effect io fn boot(cap: IO) {
  let r = router()
  get(r, "/hello", hello, cap)
  match serve(r, 8080, cap) {
    Ok(_) => print("stopped"),
    Err(e) => print("serve failed: " + e)
  }
}

boot(io)
```

Run it: `./nova run app.nova`. It really serves — the server is Python's
stdlib `http.server`, single-threaded. There is no config file, no
annotation processor, no build step.

## Routing with typed path params

```nova
get(r, "/users/{id: Int}", showUser, cap)
```

- `{id: Int}` converts the path segment to an `Int`. `/users/42` works;
  `/users/abc` is a **400** with `{"error": "path param 'id' must be Int"}`.
- Supported types: `Int`, `Float`, `String`, `Bool`.
- No route matches → **404** with `{"error": "no route for GET /..."}`.
- Patterns are validated at **check time** when they are literals:
  `/users/{id}` (no type) is `E_ROUTE`, not a runtime surprise.
- Method shorthands: `get`, `post`, `put`, `delete`, `patch`. Or the
  explicit form: `route(r, "GET", "/hello", hello, io)`.

Handlers are `effect fn (req: Request) -> Response` — or, more usefully,
`-> Result[Response, Response]` (see below). The checker validates the
handler's signature at the `route()` call: wrong arity, wrong param type,
or a pure function where an effect is needed are all compile-time errors.

## Request data

| Builtin | Returns | Notes |
|---|---|---|
| `reqMethod(req)` | `String` | `"GET"`, `"POST"`, … |
| `reqPath(req)` | `String` | path without query string |
| `reqBody(req)` | `String` | raw body |
| `reqJson(req)` | `Result[Json, String]` | parsed body; `Err` on malformed JSON |
| `param(req, name)` | `Option[String]` | raw path param |
| `paramInt(req, name)` | `Option[Int]` | typed path param (`{id: Int}`) |
| `query(req, name)` | `Option[String]` | query string |
| `header(req, name)` | `Option[String]` | case-insensitive |

## JSON binding: Nova types are the schema

There is no separate schema language. You extract fields with
`jsonGet`/`jsonStr`/`jsonInt`/`jsonFloat`/`jsonBool`/`jsonList`, and every
failure is a value you handle — usually a structured 400:

```nova
let title = match jsonGet(body, "title") {
  Some(v) => match jsonStr(v) {
    Some(t) => Ok(t),
    None => Err(web.jsonErr(400, "field 'title' must be a string"))
  },
  None => Err(web.jsonErr(400, "missing field 'title'"))
}?
```

`toJson(v)` serializes any Nova value (data classes become JSON objects);
`jsonResponse(status, v)` builds the response with the right content type.

## Result → HTTP mapping

A handler returning `Result[Response, Response]` maps errors to HTTP:

- `Ok(resp)` → served as-is.
- `Err(resp)` → **that response is served** (your 400, 404, 401…).
- `Err(other)` → 500 `{"error": "handler error: ..."}`.
- A handler that throws (Nova runtime error) → 500, never a dropped
  connection.

This is why `?` shines in handlers: `let body = web.needJson(req)?`
turns malformed JSON into a 400 in one line.

## Middleware

Middleware is `effect fn (req: Request) -> Option[Response]`:

- `Some(resp)` short-circuits — the response is served, routes never run.
- `None` continues to the next middleware, then the routes.

```nova
effect fn requireAuth(req: Request) -> Option[Response] {
  if reqMethod(req) == "GET" { return None }
  return match query(req, "key") {
    Some(k) => if k == "nova" { None } else {
      Some(web.jsonErr(401, "bad key"))
    },
    None => Some(web.jsonErr(401, "missing ?key="))
  }
}

use(r, requireAuth)
```

There is no `next()` callable — the type says it all.

## Static files

```nova
staticDir(r, "/static", "./public")
```

Serves files under `./public` at `/static/*`, with content-type detection
and path-traversal protection (`/static/../secret` is rejected).

## Request logging

Every request logs to stdout automatically:

```
[boot] listening on http://127.0.0.1:8080
[boot] GET /users/42 -> 200 (0.4ms)
[boot] GET /users/abc -> 400 (0.2ms)
```

Logging is unconditional — it is part of the framework, not an effect you
opt into. (Per-request opt-out is future work.)

## Capabilities and effects

- `serve`, `route`, `dbOpen` need the `IO` capability (passed explicitly)
  and the `io` effect: `effect io fn boot(cap: IO)`.
- Handlers must be `effect fn` (they run IO); pure functions are rejected
  at check time.
- `serve` blocks forever. It is in `BLOCKING_BUILTINS`: calling it inside
  an `async fn` is a check-time error.

## What Nova Boot is not (yet)

- **Single-threaded.** Requests are handled sequentially. Fine for
  internal tools and demos; not for production load. A threaded or async
  server is future work.
- **HTTP/1.1 only**, no TLS termination (put it behind a reverse proxy),
  no WebSockets, no HTTP/2.
- **No router nesting / groups** yet — one flat router per app.

See `examples/boot-api.nova` (full CRUD API) and `showcase/` (complete
apps) for working code.
